# F4.1 — AI form reader screens + Apply Center redesign

Status: **built 2026-10-26** (owner approved all seven defaults). Frontend for backend P4c (`job_finder_api` commit `b24fcef`,
CLAUDE.md §6.18). The owner asked for a cute, current-trend look like the Dashboard.

## 1. Why

- **P4c is invisible in the app.** The backend can now auto-apply on Ashby, SmartRecruiters, Workable and nine more
  sites (adapter `generic`), but the frontend:
  - only knows `greenhouse | lever | linkedin`;
  - has no switch for the opt-in;
  - can't show test mode;
  - can't show the form pages a run read.
- **Apply Center still has the older F4 look:** plain headers, flat cards, text-link rows, plain status lines.
  Dashboard, Jobs and Interview prep already moved to the PageKit look (eyebrow chip, big header with stat chips,
  16 px cards with soft shadow, icon tiles, gradient bars, pill tabs, motion).

## 2. Look and feel (all Apply Center screens)

Built on `components/PageKit.tsx` + `styles/kit.css`, plus a few new kit pieces (§4) that other screens can reuse.
The trend cues, kept light so the screens stay calm and readable:

- **Bento layout:** mixed-size rounded cards (20 px radius on hero cards, 16 px elsewhere) in a 12-column grid that
  becomes one column on phones.
- **Soft glass hero:** a frosted card on a faint plum→indigo mesh gradient with the page's key numbers. The blur
  falls back to a solid card when the browser has no `backdrop-filter`.
- **Pastel status pills with a dot:**

  | State     | Pill colour | Dot           |
  | --------- | ----------- | ------------- |
  | Needs you | amber       | pulses gently |
  | Working   | blue        | shimmer       |
  | Ready     | plum        | —             |
  | Sent      | green       | ✓             |
  | Stopped   | grey        | —             |

- **"AI" sparkle:** one small sparkle icon and a gradient "beta" chip mark everything the AI form reader does.
  It is not used anywhere else, so it stays meaningful.
- **Friendly copy, no jargon:** "We read 3 pages of this form", "Page 2 asked something only you can answer",
  "Test mode: you press Submit this time".
- **Micro-motion:**
  - cards lift on hover;
  - bars fill on first show;
  - steps tick in one after another;
  - the run's "page journey" draws its line as pages are read;
  - a small confetti burst (≈1 s, canvas-free CSS) on a confirmed submit.
  - All motion is off under `prefers-reduced-motion`.
- **Dark mode** through the existing tokens. Phone width (375 px): single column, no horizontal scroll, 44 px tap
  targets.

## 4. Shared pieces (new in the kit)

- `StatePill` (state → tone, dot, label).
- `PageJourney` (stepper with thumbnails).
- `GlassHero`.
- `ProgressRing` (small, reuses `ScoreRing` maths).
- `Lightbox`, built on the existing `Dialog`.
- `SparkleChip`.
- `Confetti`: CSS only, respects reduced motion.

Each one has a unit test. Dashboard and Interview screens are untouched.

## 5. Data and API

- **Types:** regenerate `src/lib/api/schema.d.ts` from the backend OpenAPI. This adds `adapter: "generic"`, the
  new settings fields (`allow_generic`, `generic_notice`, `generic_submit_enabled`, `caps.generic_per_day`) and the
  new run fields (`steps`, `vision`). Proof kind `step` is plain text and needs no type change.
- **`applyApi.ts`:**
  - `putSettings({allow_generic})`;
  - new error codes `generic_off`, `generic_cap`, `generic_test_mode`;
  - a run in `queued` after an answer keeps polling (same as other moving states).
- **Mocks** (`src/mocks/f4*.ts`):
  - a generic job;
  - a 3-page run that walks through `awaiting_input` → `queued` → `awaiting_review`, with step screenshots and
    `vision` usage;
  - test mode on and off;
  - the settings toggle;
  - the cap error.

  All of it can be seen with `npm run dev:mocks`.

## 6. Decisions (recommended default in bold)

1. Scope: **all Apply Center screens restyled + the AI form reader features in one pass** / only the AI form reader
   features in the current look / restyle first, features after.
2. Design source: **build straight from the Dashboard/PageKit look with the cues in §2** / make Stitch mockups of
   Apply Center + Run review first and wait for your pick (one extra round).
3. Confetti on a confirmed submit: **yes, small and once** / no.
4. Glass hero: **yes, with a solid-card fallback** / plain card like the Dashboard.
5. Turning the reader on from the Auto apply button: **inline popover with the notice** / send people to the
   Settings tab.
6. Test-mode primary action: **"Copy answers & open the job page", then "I submitted it"** / show Approve disabled
   with an explanation.
7. "AI help" cost line on a run: **show steps and cost** / steps only (hide money).

## 8. Risks

- **Busy screens:** the bento grid and motion can feel busy. Mitigation: one hero per page, sparkle only for AI,
  motion under 300 ms, and the reduced-motion switch.
- **Glass blur on low-end phones:** costly to draw. The blur radius is kept small and is turned off on phones under
  the 640 px breakpoint (solid card there).
- **Screenshots in the gallery are PNGs from the API** (`/apply/runs/{id}/proofs/{id}`). They load lazily, use the
  existing object-URL cleanup, and fetch at most 6 thumbnails at once.
